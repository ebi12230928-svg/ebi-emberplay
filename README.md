# EMBERPLAY

エンタメ専用ポイント(Embers)を使った、Stake.com / Shuffle.com 風のミニゲームサイトです。

**重要: Embersは無料の報酬でのみ入手できます。現金・ギフトカード・暗号資産・景品など、価値のあるものへの交換機能は一切なく、今後も追加しない前提で設計されています。この前提を変えると賭博に該当する可能性があるため、換金・出金機能は絶対に追加しないでください。**

## セットアップ(ローカル)

```bash
pip install -r requirements.txt
python app.py
```

起動後、`http://localhost:5000` にアクセスしてください。初回起動時に `emberplay.db`(SQLite)が自動生成されます。

## 最初の管理者を作る

1. サイトで通常どおり新規登録する
2. `app.py` の中の以下の行を、自分のユーザー名に書き換える

```python
initial_admin_username = os.environ.get("INITIAL_ADMIN_USERNAME", "ここに自分のユーザー名")
```

3. サーバーを再起動する(コンソール操作は不要です。起動するたびに、このユーザーがまだ管理者でなければ自動的に管理者になります)

管理者になると `/admin` から他のユーザーへのポイント付与・借金の設定・コードの発行・管理者権限の付与ができます。

## 報酬の拡充について

- **アワリー報酬**を新設(1時間ごとに受け取り可能・100 Embers)
- **ログインボーナス**を新設(連続ログイン日数に応じて増額、7日目以降は7日目の額でループ。1日休むとリセット)
- デイリー・ウィークリー・マンスリー・リロードの受け取り額をそれぞれ引き上げました(`config.py`で調整可能)

## ロビー画面のカルーセル化について

Stakeのような、横にスライドするカード形式に作り直しました。

- **プレーを続ける**: 自分の直近のプレイ履歴(重複なし・新しい順)から自動生成されます。まだ何もプレイしていない場合は表示されません
- **あなたへのおすすめゲーム**: 全ゲームの中からランダムに8つ選ばれます。**ページを開くたびに毎回変わります**
- 各カテゴリー(オリジナル/テーブルゲーム/スロット/その他のプロバイダー)も横スクロール形式になり、「すべて見る」から全件表示ページに移動できます
- 検索ボックスは引き続き使えます(該当しないカードは自動的に隠れます)
- **各カードにサムネイル画像を追加**しました。実在するカジノサイトの画像は著作権の関係で使えないため、ゲームごとに色付きグラデーション+絵文字アイコンで独自にデザインしています(`lobby.py`の`MECHANIC_THEME`で管理)

## 新しいゲーム・再スキンについて(Stakeのロビー画像を参考に追加)

いただいたスクリーンショットを元に、再現できるものは追加しました。

- **Rock Paper Scissors**(新規実装): ハウスとのじゃんけん勝負。引き分けはプッシュ、勝てば約1.9倍
- **「その他のプロバイダー」カテゴリー**(17件追加): Plinko Xtreme、Limbo Trader、Power of Ten、Million X、Dice 100000、Roulette 100000、Hacksaw Limbo、Limbo Go、Keno Xtreme、Cut N' Crash、Mine Drop、Line Runner、Balance、Pump、Slide、Drop the Boss、Moles ── これらは実在のカジノサイトでもよくある「同じ仕組みを別のプロバイダー名で提供する」形にならい、既存のDice/Limbo/Crash/Mines/Roulette/Keno/Plinkoのエンジンをそのまま再利用した、別名義の追加ロビー掲載です(内部のゲームロジックは元のゲームと共通です)

**あえて作らなかったもの(理由付き)**

- **ライブディーラー系**(Speed Baccarat Live、Blackjack Live、各種Roulette/Baccarat Live、Stock Market Liveなど): 実際の人間のディーラーによるリアルタイム映像配信が必要で、コードだけでは実現できません。偽の「ライブ風」演出を作ることも、利用者に誤解を与えるため行っていません
- **実在ブランドのスロット**(Gates of Olympus、Sugar Rush、Duel of Olympusなど): Pragmatic PlayやTitan Gamingなどが権利を持つ商標・著作物のため、同じ名前・同じ絵柄では作成していません。同じ雰囲気の独自スロットは既存の14テーマ(Egyptian GoldやDragon's Hoardなど)でカバーしています

## 新しいゲームについて

- **American Roulette**: ヨーロピアンルーレットに00を追加したバージョン。配当はヨーロピアン版と同じですが、ポケット数が1つ増える分、的中率がわずかに下がります
- **Red Dog**: 2枚のカードの間に3枚目が入るかを予想するシンプルなカードゲーム。全パターンを実際に総当たりして期待値を検証済みです(house edge約10.6%)
- **Andar Bahar**: ジョーカーと同じ数字のカードが「Andar」「Bahar」どちらに先に出るかを予想するインドの伝統的なカードゲーム。確率を正確に計算した上で配当を設定しています(どちらも約5.9%のhouse edge)
- **Craps**: Pass LineまたはDon't Passを選んでサイコロを振る、カジノの定番ゲームの簡易版です
- **Three Card Poker**: Ante(基本ベット)を賭けて3枚配られ、Play(続行)かFold(降参)を選ぶポーカー系ゲーム。役がStraight以上ならAnteボーナスも付きます。役の判定ロジック(Straight Flush・Three of a Kind・Straight・Flush・Pair・High Card、3枚特有のQ-K-Aやウィーラー処理も含む)は実際にテストして正しく動作することを確認済みです

## 借りる機能について

- ウォレット画面(`/wallet`)から、誰でも自分から指定額(`config.py`の`LOAN_AMOUNT`、デフォルト3,000)Embersを借り入れられます
- すでに借金がある間は、完済するまで再度借りることはできません
- それ以外の返済ルール(勝利分が返済に充当される、完済時に1%だけ残高化される、1ヶ月未返済でマンスリー凍結、など)は管理者が設定する借金と同じです

## お知らせ掲示板について

- `/announcements` ページで、管理者が投稿したお知らせを全プレイヤーが閲覧できます(VIP限定ではありません)
- 管理者パネル(`/admin`)から投稿・削除ができ、投稿すると全プレイヤーに通知が届きます
- ロビー画面の上部にも、最新3件が表示されます
- これはVIPラウンジ内のお知らせ欄(VIP限定)とは別物です。使い分けの目安:全員向けのお知らせ→掲示板、VIP向けの特別な告知→VIPラウンジ

## アニメーションについて

- **残高(オドメーター)**: 数字が変わった桁だけがパタパタとめくれるアニメーションに変更しました
- **各ゲームの勝敗表示**: 勝ったときはポップして光る演出、負けたときは横に揺れる演出を、全ゲーム共通で追加しました(`static/js/balance.js`の`EmberPlay.flashResult()`という共通関数を使っています)

## VIP特典について

管理者が認定したVIPユーザーには、以下の特典が自動的に適用されます(`config.py`で数値を調整できます)。

- **レーキバック2倍**(通常3% → VIP 6%)
- **アワリー報酬が30分ごとに受け取り可能**(通常は1時間ごと)
- **XP獲得量1.5倍**(レベルアップ・実績解除が早くなる)
- **借金の上限アップ**(通常3,000 → VIP 8,000)
- **デイリースピンが高額プライズ仕様**(通常100〜2,500 → VIP 300〜6,000)
- VIPラウンジ(専用お知らせ・試合情報)の利用

ウォレット画面には、VIPの人には現在の特典一覧が、VIPでない人には「VIPになるとこんな特典が」という案内が表示されます。

## VIPラウンジについて

- 管理者パネル(`/admin`)から、ユーザーごとに「VIPにする/解除」を切り替えられます(自動昇格の条件などは現状ありません)
- VIPになると本人に通知が届き、ナビに金色の「VIPラウンジ」リンクが表示されます
- ラウンジ内の「お知らせ」欄は管理者のみ投稿・削除できます(例: 「今夜21:00からDAZNでプレミアリーグの放送があります」といった告知に利用できます)。**外部の配信サービス(DAZNなど)の映像そのものを埋め込むことは著作権上できないため、あくまで告知・案内にとどめています**
- 試合データはスポーツベット機能と同じTheSportsDBのデータを再利用しています

## チャット機能について

- 全ログインユーザーが利用できます(VIP限定ではありません)
- 本格的なWebSocketではなく、**2.5秒ごとに新着メッセージを取得するポーリング方式**です。RailwayやRenderのような常時稼働型のホスティングだけでなく、PythonAnywhereやVercelのようなサーバーレス環境でも問題なく動作するよう、あえてこの方式にしています
- 荒らし対策として、1人あたり1.5秒に1回までの投稿制限と、1メッセージ500文字までの制限を設けています
- 管理者・VIPのメッセージには、それぞれ色分けとラベルが表示されます

## スポーツベット機能について

[TheSportsDB](https://www.thesportsdb.com)という無料のスポーツデータAPIを使い、実際の試合結果を取得しています。

- 無料の共通APIキー(`123`)を使用しているため、**登録は不要**です
- ページを開くたびに最新の試合日程・結果を取得しますが、無料枠を節約するため**5分に1回だけ**外部APIを呼び出す仕組みになっています
- 賭けたあと試合が終了すると、次に誰かが`/sportsbook`ページを開いたタイミングで自動的に結果が判定され、的中していればEmbersが付与されお知らせが届きます
- **オッズはチームの強さ(現在の順位表の勝ち点)に応じて自動計算されます**。勝ち点差が大きいほど、強い方の配当は下がり、弱い方の配当は上がります(どのオッズでも約8%のhouse edgeになるよう正規化済みです)。Champions Leagueのように順位表を参照できない大会は、暫定的にデフォルトのオッズ(勝ち1.9倍・引き分け3.2倍)になります
- 無料APIキーは共有のものなので、アクセスが集中する時間帯は取得に失敗することがあります(その場合は該当リーグの更新がスキップされるだけで、エラーにはなりません)

## ゲームごとの配当倍率調整について

- 管理者パネル(`/admin`)の一番上に、全35ゲーム分の「配当倍率スケール」の一覧があります
- 1.0が通常の状態です。0.8に設定するとそのゲームの配当が全体的に20%下がり(難しくなり)、1.2に設定すると20%上がります(甘くなります)
- 設定できる範囲は0.1x〜3.0x です
- ゲーム内部の当選確率(サイコロの出目やカードの引き方など)自体は変更されません。あくまで「当たったときにもらえる量」だけを一括調整する仕組みです
- スロットは14テーマありますが、管理を簡単にするため全テーマ共通の倍率1つで調整する仕様にしています(テーマごとに個別設定したい場合はご依頼ください)
- 引き分け・プッシュ(賭け金がそのまま返ってくる結果)は調整の対象外です(常に賭け金がそのまま返ります)

## データベースの自動マイグレーションについて(重要)

これまで、モデルに新しい列を追加するたびに「データベースを作り直す(`rm emberplay.db`)」操作が必要でしたが、**今後は不要になります**。

- `app.py`起動時に、モデル定義と実際のデータベースの構造を比較し、**足りないテーブル・列だけを自動的に追加**する仕組み(`_auto_migrate`)を組み込みました
- 既存のデータ(ユーザーアカウント・残高など)は消えずにそのまま引き継がれます
- ALTER TABLEでの列追加のみに対応しています(列の削除・型変更・リネームには対応していません。今後そういった変更が必要な場合は個別にご相談ください)
- 実際にSQLiteで「既存データを保持したまま新しい列が追加されるか」を検証済みです

## 📧🔐 Googleログイン + パスキー + メール通知 + Gmail連携ログ + オフライン人数表示

大きく5つ実装しました。まず、**特に重要な正直なお知らせ**からお伝えします。

### ⚠️ 正直なお知らせ:パスキー機能は、コード上は実装済みですが、実機テストが必要です
パスキー(WebAuthn)は非常に専門的な暗号技術を使う仕組みで、`webauthn`という専用のライブラリを使って実装しました。ただし、**このライブラリは私の作業環境にインストールできなかった(ネットワーク制限のため)**ため、実際にライブラリを動かしての最終確認ができていません。コードはライブラリの公式な使い方に沿って書いていますが、**実際にデプロイして試した際に、細かい不具合が出る可能性があります**。もし動かない場合は、その時のエラーメッセージを教えていただければ、すぐに修正します(これまでも、実際のエラーを見ながら一緒に直してきた通りです)。

### 1. Googleアカウント(Gmail)でログイン・連携
Discordと同じ、安全なOAuth2方式で実装しました。プロフィール画面から「Gmailでログインして連携する」ボタンで連携できます。パスワードは一切こちらに送られません。

### 2. パスキー(指紋・顔認証でログイン)
プロフィール画面から、この端末の指紋・顔認証を「パスキー」として登録できます。登録後は、ログイン画面に表示される「🔐 パスキーでログイン」ボタンから、パスワード無しでログインできます。**PWA(アプリ)としてお使いの場合、特に簡単になります**。生体情報そのものは、常に端末内にのみ保存され、サーバーには一切送信されません。

### 3. Google連携済みのメールアドレスに、キャンペーン・お知らせを送信
管理者が「全員へのお知らせ」を送ると、**Google連携済みのユーザーには、あわせてGmailにもメールが届く**ようにしました。

**設定と正直な注意点**: 送信には管理者ご自身のGoogleアカウントの「アプリパスワード」が必要です(`local_secrets.py`に設定)。また、PythonAnywhereの無料プランでは、Gmailの送信サーバー(smtp.gmail.com)が通信許可リストに入っていない場合、送信できない可能性があります(プッシュ通知の時と同じ制約です)。

### 4. Gmail連携ログ(全員分を記録)
ご要望通り、「誰が・いつGoogle連携したか」を**全員分**記録する専用ログを追加しました。管理画面に「📧Gmail連携」タブがあります(トークンなどの認証情報は記録していません)。

### 5. オンラインの横にオフライン人数も表示
ロビー画面の「🟢 オンライン」の横に、「⚪ オフライン」人数も表示するようにしました(登録ユーザー総数からオンライン人数を差し引いた数)。誰でも見える場所に表示されます。

### 必要な設定(反映方法)
1. Google Cloud Console(https://console.cloud.google.com/apis/credentials)でOAuthクライアントIDを作成し、`GOOGLE_CLIENT_ID`・`GOOGLE_CLIENT_SECRET`・`GOOGLE_REDIRECT_URI`(`https://あなたのドメイン/google/callback`)を`local_secrets.py`に設定
2. メール送信用に、`https://myaccount.google.com/apppasswords` でアプリパスワードを発行し、`MAIL_SENDER_EMAIL`・`MAIL_SENDER_APP_PASSWORD`を設定
3. `WEBAUTHN_RP_ID`・`WEBAUTHN_ORIGIN`にサイトのドメインを設定(デフォルトのままでも動くはずです)
4. `pip3.10 install --user -r requirements.txt` で、追加した`webauthn`ライブラリをインストール
5. 「Web」タブで「Reload」

実装後、①Google連携ログの記録・表示、②オンライン/オフライン人数の計算ロジック、③各画面の実際のレンダリングを検証済みです。パスキー機能のみ、上記の理由により実機での最終確認をお願いします。

## 🚨 サイト障害の対応 + アプリとして開いた場合のログイン保持を実装

### サイトが表示されなくなっていた件
`push_notifications.py`がアップロードされていなかったこと、その後`config.py`が古いバージョンのままだったことが原因でした。Bashコンソールから直接ファイルを作成する方法で復旧いただき、現在は正常に動作しています。ご協力ありがとうございました。

## 🎵 音ズレのさらなる改善(+ 技術的な制約について正直な説明)

**正直にお伝えする必要があります。** 「曲の音を最初から最後まで取得して、そこから譜面(ブロック)を生成する」というご要望は、**技術的に実現できません**。YouTubeの埋め込みプレイヤーは、著作権保護のためJavaScriptから音声データ(波形)に直接アクセスできない仕組みになっており、また当方針としても音源そのものをダウンロード・解析することはできません。そのため、実際の音の鳴るタイミングを検出して譜面を作ることはできず、これまで通り「BPM(テンポ)を指定して、そこから計算で譜面を生成する」方式が、現状で唯一実現可能な方法になります。

**その上で、ズレをできる限り減らす改善は行いました。** 再生を始めた直後はバッファリングの影響でズレが出やすいため、**開始直後の数秒間は0.3秒〜1秒間隔で頻繁に同期を取り直し**、安定してきたら通常の2秒間隔に切り替えるようにしました。これにより、特に曲の序盤で起きやすいズレを素早く吸収できるはずです。

より正確に音に合わせたい場合は、引き続き「BPM」と「最初の拍の位置(イントロを飛ばす秒数)」を、曲に合わせて手動で指定していただく方法をおすすめします。

## 📱 フリック(上スライド)がスマホでページスクロールに奪われる問題を修正

**原因が分かりました。** 以前、ダブルタップズーム対策として設定した`touch-action: manipulation`は、ズームは防げるものの**上下方向のスワイプ(スクロール)までは防げない**設定でした。そのため、フリックノーツで上にスライドしようとすると、スマホのブラウザが「ページをスクロールしたいのだな」と誤解し、ノーツの操作より先にページが動いてしまっていました。

**修正内容**: タップ操作エリアの`touch-action`を、あらゆるブラウザ標準のジェスチャーを無効にする`none`に変更しました。あわせて、JS側でも指の動きを検知した際に明示的にブラウザの既定動作を打ち消す処理を追加し、二重で対策しています。

## 📱 スマホでの表示崩れを修正

複数のページで、スマホ(特に幅の狭い画面)で表示が崩れる問題を修正しました。

**主な原因と対策**:
- **横方向にはみ出す要素への安全策**: `html, body`に`overflow-x: hidden`を設定し、個々の要素が多少はみ出しても、ページ全体が横スクロールしてしまうことがないようにしました
- **固定列数のグリッド**: キャラクター選択・ガチャ演出などで使っていた「常に4列/5列/6列」のグリッドを、画面幅に応じて自動的に列数が減る仕組み(`.grid-2`〜`.grid-6`)に置き換えました(400px以下で3列、340px以下で2列に自動調整)
- **横並びレイアウトの折り返し**: `display:flex`を使っている箇所(フォームやボタン列など)に`flex-wrap: wrap`を機械的に追加し、画面が狭い時は自動的に折り返すようにしました(横スクロールが意図的な「最近の大勝ち」フィードなどは対象外にしています)
- **管理画面の表**: ユーザー一覧など列数の多い表を、横スクロール可能なコンテナで囲みました(表を無理に画面幅に収めようとして文字が潰れる、という問題を防ぎます)
- **固定px幅の要素**: 一部のゲームで使っていた固定幅(`width: 220px`など)を、`max-width`を使った可変幅に変更しました

実際にCSSの括弧バランス・全テンプレートのdivタグの開閉バランスをチェックスクリプトで検証済みです。

- **🔥 レイド** — まあまあ強い。標準的な編成では厳しく、育成した強いキャラクターや複数人での協力が現実的になります
- **💀 ラスボス** — かなり強い。1人ではほぼ勝てず、フレンドとの協力プレイが前提の難易度です
- **♾️ エンドレスモード** — 倒す(生き残る)たびに敵がどんどん強くなっていき、力尽きるまで続きます。到達した数だけ報酬が積み上がります(ソロ専用)

**正直な調整の過程**: 最初にレイド・ラスボスの数値を決めた際、「難易度ティア」と「協力プレイの人数によるスケーリング」を両方フルに掛け算してしまい、4人协力でもラスボスが理論上倒せない(何回シミュレーションしても勝率0%)という数値になってしまいました。これに気づき、ティアの強さ(レイド・ラスボス)は固定の強さとして設定し、協力プレイの人数はその固定の強さに対してどれだけ多くのキャラクターをぶつけられるかで挑む、という設計に直しました。最終的に実際に1000回前後のシミュレーションを繰り返し、①レイドは最強級の編成でも薄氷の勝率 ②ラスボスは1人ではほぼ不可能・2人以上で現実的 ③エンドレスは平均3体前後で力尽きる、というバランスになるよう調整しています。

**タワーディフェンスのラスボスについて**: 大量の雑魚敵ではなく、非常に頑丈な敵(👑)が1体だけ現れる特別な形式にしました。

## 👥 フレンドとの協力プレイ・⚔️ RPGボス討伐(新機能)

### 協力プレイ(スクワッド)システム
タワーディフェンス・RPGボス討伐の両方で、**フレンドと部屋を作って一緒に挑戦できる**ようになりました。

- 部屋を作ると、フレンドがロビー画面から参加できます(最大4人)
- 参加者それぞれが自分の持ちキャラクター(最大4体)を持ち寄り、全員分を結集した編成で挑みます
- **参加人数に応じて敵が強くなります**(難易度倍率 = 1 + (人数-1) × 0.8。4人なら3.4倍)
- クリア報酬は参加者全員に配られます(タワーディフェンスを実際にプレイするのは部屋の主催者(ホスト)で、他のメンバーは結果を待ちます)

### ⚔️ RPGボス討伐(新モード)
`/rpgboss` から、選んだキャラクター編成でボスに挑む、ターン制の自動バトルを追加しました。チームの合計攻撃力とボスの攻撃力がターンごとにぶつかり合うアニメーション付きバトルです。

**正直な調整の過程**: 最初に実装した数値では、標準的な編成のソロプレイでも常に100%勝利してしまい、人数によるスケーリングの意味がほとんどありませんでした。実際に数百〜1000回のシミュレーションを繰り返し、①弱い編成は確実に負ける ②標準的な編成は五分五分程度の緊張感がある ③編成を強化する・協力プレイで人数を増やすと有利になる、というバランスになるよう、ボスのHP・攻撃力・乱数の幅を調整し直しました。

**正直な制約**: タワーディフェンスの人数スケーリングは同じ考え方(難易度倍率)を適用していますが、RPGボス討伐のような詳細な数値シミュレーションでの検証はできていません(タワーディフェンスは配置・射程などの空間的要素が絡むため、簡単な数値シミュレーションでは再現できませんでした)。実際に遊んでみて極端に簡単/難しいようであれば、教えてください。調整します。

## 🎴 ガチャ・図鑑・🏰 タワーディフェンス(新システム)

Embersを使ってキャラクターを集め、タワーディフェンスで活躍させる新しいゲームシステムを追加しました。

**設計上の工夫**: 実際の戦闘計算(敵の移動・当たり判定・ダメージ計算)は全てブラウザ側でリアルタイムに処理し、サーバーは「キャラクターを実際に持っているか」の検証と結果に応じた報酬付与だけを担当する設計にしました。パスの接続性(敵が正しく道を通れるか)やキャラクターの排出率は実際にテストコードで検証済みです。

- ±1.0で「常に勝ち」「常に負け」になります(確率は100%が上限なので、これが数学的な限界です。それ以上の値を入れても効果は変わりません)

- 補正によって勝敗が変わった場合、画面に表示されるカード・ダイス目・ルーレットの出目なども、結果と矛盾しないよう自動的に調整しています

## 画面配信機能について

`/stream` から、ブラウザ標準のWebRTC機能を使った画面配信ができます。

- **仕組み**: 配信者のブラウザが画面映像をキャプチャし(`getDisplayMedia()`)、視聴者のブラウザへ直接P2P(ブラウザ同士が直接つながる通信)で送ります。**サーバーには映像データが一切通りません**。サーバー側が中継するのは、接続を確立するための小さなテキスト情報(シグナリング)だけです
- 音声・マイクは使用していません(映像のみ)
- 同時に配信できるのは1つだけです。すでに誰かが配信中の場合、別の人は開始できません(終了を待つか、管理者が強制終了できます)
- **正直な制約**: これは配信者から視聴者へ1対1の接続を人数分作る方式のため、少人数(目安5〜10人程度)向けです。またSTUN(接続経路を見つけるための無料の補助サーバー)のみを使っており、TURN(有料の中継サーバー)は使っていないため、双方のネットワーク環境によっては接続できないケースが稀にあります(多くの家庭・モバイル回線では問題なく動作します)

## イベント(ウェイジャーレース)機能について

「イベント」は、期間限定の**賭け金ランキング大会**として実装しました。参加登録は不要で、対象期間中のプレイ額(合計プレイ料)が自動的にカウントされ、上位者に賞金が自動で付与されます。

- 管理者パネルから、タイトル・開始/終了日時(UTC)・順位別の賞金(カンマ区切り、例: `5000,3000,2000`)を入力してイベントを作成します
- 作成すると全プレイヤーに通知が届きます
- `/events`ページで、開催中イベントのリアルタイムなランキング(現在の順位・プレイ額・想定賞金)を確認できます
- 終了日時を過ぎると、次に誰かが`/events`を開いたタイミングで自動的に順位が確定し、賞金が付与されます(お知らせにも結果が届きます)
- カウント対象は通常のカジノゲーム(`BetRecord`)のプレイ額のみです。スポーツベットは現在集計対象に含まれていません(必要であれば追加できます)
- 日時の入力欄はUTC(協定世界時)基準です。日本時間で開催したい場合は、日本時間から9時間引いた時刻を入力してください(例: 日本時間20:00に開始したい場合は11:00と入力)

## プレゼント企画(Giveaway)機能について

- 管理者パネル(`/admin`)からタイトル・賞金額・当選人数を入力して企画を作成できます
- 作成すると全プレイヤーに通知が届き、`/giveaways`ページから参加できます(1人1回まで)
- 管理者が「抽選する」を押すと、参加者の中からランダムに当選者を選び、自動的にEmbersを付与します(全員に当選者の通知が届きます)
- 過去の企画の結果は`/giveaways`ページの下部からいつでも確認できます

## 借金機能について(重要・仕様の確認をお願いします)

ご依頼内容の説明がやや解釈の余地があったため、以下のように実装しました。想定と違う場合は教えてください、調整します。

1. 管理者が `/admin` から特定ユーザーに借金を設定すると、**そのユーザーの現在の残高は0になり**(=すべて「借金ポイント」として没収)、借金額が記録されます。本人に通知が届きます。
2. 借金がある間、**ゲームでの勝利分は残高に反映されず、全額が借金の返済に充てられます**。デイリー/ウィークリーなどの無料報酬は今までどおり通常に受け取れます(遊ぶための元手として使えます)。
3. ちょうど借金を完済した回に勝利分が余った場合、その余った分の**1%だけ**が残高として反映され、以降は通常どおりプレイできます。
4. **借金を1ヶ月以内に返済しなかった場合、マンスリー報酬が借金完済まで使えなくなります**。
5. 管理者は「借金を免除する」でいつでも借金をリセットできます。

## コード機能について

- **「1人1回まで」タイプ**: 何人でも使えますが、同じ人は1回しか使えません。発行時に全員へお知らせが届きます。
- **「全体で合計N回まで」タイプ**: 1人1回という制限はなく、合計でN回使われたら終了です(同じ人が複数回使うことも可能です)。こちらも発行時に全員へお知らせが届きます。

## 学校などフィルターの効きやすい環境での利用について

ブランド名を「EMBERPLAY」、通貨を「Embers」とし、UI上の文言も「賭け金」→「プレイ料」、「ベット」→「選択」のように、賭博を直接連想させる単語を避けるよう調整しています。

ただし、これは**完全な保証ではありません**。学校などのネットワークフィルター(Bark、GoGuardian、Securlyなど)は、単語だけでなくドメインの評判・カテゴリ分類・画像解析など複数の方法でサイトを判定するため、必ず通過できるとは限らない点をご理解ください。心配な場合は、実際に導入予定のネットワークで事前にアクセステストすることをおすすめします。

## Renderへのデプロイ手順(クレジットカード登録不要)

[Render](https://render.com) は、Railwayと似た使い勝手(GitHub連携→自動デプロイ)でありながら、**無料プランの利用にクレジットカード登録が不要**なサービスです(2026年時点で複数の情報源で確認済み)。

**知っておいてほしい制限**
- 無料プランは15分アクセスがないとスリープし、次のアクセス時に30〜60秒ほど起動待ちが発生します
- Render自体の無料Postgresは期限付き(30〜90日で削除)なので、**Vercelの手順で案内したNeon/SupabaseのPostgresをそのまま使う**ことを強くおすすめします(同じ`DATABASE_URL`をそのまま使い回せます)

**手順**

1. **外部のPostgresを用意する**(Vercel用に作成済みなら、そのまま使えます。まだなら[Neon](https://neon.tech)などで無料作成し、接続URLを控えておく)
2. **GitHubリポジトリを作る**(すでにお持ちなら、このままでOKです)
3. **Renderでアカウント作成**: [render.com](https://render.com) にGitHub/Google等でサインアップ(クレジットカード不要)
4. **New +** →「Web Service」→ 対象のGitHubリポジトリを選択
5. このプロジェクトには `render.yaml` を同梱しているので、Renderが自動的に設定を読み込みます(読み込まれない場合は、以下を手動で入力してください)
   - Build Command: `pip install -r requirements.txt`
   - Start Command: `gunicorn wsgi:app`
6. **環境変数を設定**(「Environment」タブ):
   - `DATABASE_URL` = 手順1で控えたPostgresの接続URL
   - `SECRET_KEY` = ランダムな文字列(`render.yaml`により自動生成される場合はそのままでOK)
   - `INITIAL_ADMIN_USERNAME` = 最初に管理者にしたいユーザー名
7. **Create Web Service** を押してデプロイ完了を待つ
8. 発行される `xxxx.onrender.com` のURLでアクセスできます

## Vercelへのデプロイ手順(ドメイン取得なしでOK)

**重要な前提**: Vercelは「サーバーレス」という仕組みで動くため、SQLiteのようなファイルベースのデータベースは使えません(リクエストのたびにデータが消えます)。**必ず外部のPostgresデータベースを用意してください**(下記手順内で案内します)。

1. **外部のPostgresデータベースを用意する**: [Neon](https://neon.tech)や[Supabase](https://supabase.com)は無料枠があり、数分でPostgresデータベースを作成できます。作成後、接続用のURL(`postgresql://...`から始まる文字列)を控えておいてください。
2. **GitHubリポジトリを作る**: このプロジェクトのファイル一式をGitHubリポジトリにpushしてください。
3. **Vercelでプロジェクト作成**: [vercel.com](https://vercel.com) にログイン(GitHubアカウントでのログインが簡単です)→「Add New...」→「Project」→ 先ほどのリポジトリをImport。
4. **環境変数を設定**: プロジェクトの「Settings」→「Environment Variables」で以下を追加してください。
   - `DATABASE_URL` = 手順1で控えたPostgresの接続URL
   - `SECRET_KEY` = ランダムな長い文字列(推測されないもの)
   - `INITIAL_ADMIN_USERNAME` = 最初に管理者にしたいユーザー名
5. **デプロイ**: 「Deploy」を押すだけです。Vercelは `requirements.txt` からPythonアプリだと自動検出し、`pyproject.toml` に書かれた `wsgi:app` をエントリポイントとして起動します。静的ファイル(CSS/JS)は `public/static/` に同梱済みで、Vercelが自動的にCDN経由で配信します。
6. **公開URLの確認**: デプロイが完了すると `xxxx.vercel.app` の形式のURLが発行されます。これが公開URLです。
7. **(任意)独自ドメインを後から追加したい場合**: プロジェクトの「Settings」→「Domains」からお持ちのドメインを紐づけられます。

### コードを更新したいとき
GitHubにpushするだけで、Vercelが自動的に再デプロイしてくれます。

### Vercel特有の制限について
- 1回のアクセスあたりの処理時間に上限があります(`vercel.json`で30秒に設定済み)。通常の利用では問題になりません。
- アプリ全体のサイズが500MBを超えないようにしてください(現状のEMBERPLAYは十分小さいです)。

## (代替案)Railwayへのデプロイ手順

サーバーレスではなく、常時起動する通常のサーバーとして動かしたい場合はRailwayも使えます。こちらはSQLiteでもある程度動きますが、やはりPostgresの利用を推奨します。

1. **GitHubリポジトリを作る**: プロジェクト一式をGitHubにpush。
2. **Railwayでプロジェクト作成**: [railway.app](https://railway.app) →「New Project」→「Deploy from GitHub repo」→ リポジトリを選択。
3. **データベースの追加(推奨)**: 「+ New」→「Database」→「PostgreSQL」を追加。自動的に `DATABASE_URL` が渡されます。
4. **環境変数を設定**: 「Variables」タブで `SECRET_KEY` と `INITIAL_ADMIN_USERNAME` を追加。
5. **デプロイ**: `Procfile`(`web: gunicorn wsgi:app --bind 0.0.0.0:$PORT`)を自動検出して起動します。
6. **公開URLの確認**: 「Settings」→「Networking」から `xxxx.up.railway.app` のURLが発行されます。

## 設定値の変更

`config.py` の `Config` クラスで、報酬額・クールダウン時間・レーキバック率などを調整できます。各ゲームの house edge(控除率)はそれぞれの `games/*.py` 内で個別に設定しています。

## 本番運用時の注意

- `config.py` の `SECRET_KEY` を推測されない値に変更してください(環境変数 `SECRET_KEY` で上書き可能です)。
- Railwayなど本番環境ではPostgreSQLの利用を推奨します(上記デプロイ手順を参照)。
- HTTPS環境での運用を推奨します(Railwayは標準でHTTPSが有効になります)。
